## Commands

Everything except Composer runs through Sail. Composer runs on the host (see
`docs/local-development.md`). Don't use the `composer dev` / `composer setup`
scripts: they're starter-kit leftovers that run `npm` on the host.

```sh
vendor/bin/sail up -d                                # app + Postgres
vendor/bin/sail bun run dev                          # Vite with hot reload
vendor/bin/sail bun run build                        # production build
vendor/bin/sail bun run types                        # tsc --noEmit
vendor/bin/sail bun run lint                         # ESLint, fixes in place
vendor/bin/sail bin pint --dirty                     # PHP formatting
vendor/bin/sail artisan test --compact               # full suite (in-memory SQLite)
vendor/bin/sail artisan test --compact tests/Feature/Mcp/CreateVendorTest.php
vendor/bin/sail artisan test --compact --filter=testName
vendor/bin/sail artisan wayfinder:generate --with-form
```

Wayfinder output (`resources/js/actions`, `resources/js/routes`,
`resources/js/wayfinder`) is gitignored and generated by the Vite plugin, so a
fresh worktree has none until Vite runs or you generate it.

## Architecture

The product is HuurMaar, a catalog of rental services from local vendors.
Laravel 12 + Inertia v3 + React 19 + Tailwind v4/shadcn, Postgres 18,
Fortify for auth. The default locale is `nl`, with `en` as fallback.

**Two separate entry points with their own auth:**

- **Web app** (`routes/web.php`): Inertia pages for vendor users (`User`).
  Registration and login come from Fortify. A user owns at most one `Vendor`.
  Dashboard routes redirect to `/onboarding` until the user has created one.
- **MCP ingress server** (`routes/ai.php`, `app/Mcp/Servers/IngressServer.php`):
  admin tools for importing vendors and services. It's protected by
  `auth:sanctum` plus the `ingest` gate (`AppServiceProvider`), which only lets
  `Admin` models through. `Admin` is a separate authenticatable with Sanctum
  tokens, distinct from `User`. Vendors created here are "unclaimed"
  (`user_id` is null, see `Vendor::isClaimed()`).

`.claude/rules/architecture.md` requires keeping these two domains' logic
separate. Don't share code between MCP tools and controllers.

**Domain model:** `Vendor` → `Service` (has a `public_id` like `svc_xxxxxxxxxx`)
→ `ServicePrice` (fixed/variable pricing modes and units) plus `ServiceMedia` and
an optional `ServiceCustomCategory` when the category is `other`. Prices are
stored in minor units (EUR cents).

**Public URLs:** the catch-all `/{vendorSlug}` and
`/{vendorSlug}/services/{servicePublicId}` routes sit at the bottom of
`web.php`. Any new top-level path must be declared before them and added to
`config/reserved_vendor_slugs.php`, so that no vendor can claim it as a slug.

**Config + translation pattern:** selectable values live as locale-neutral keys
in `config/service_categories.php` and `config/service_pricing_units.php`.
Their labels come from `lang/<locale>/config-<name>.php`. Each page gets its
copy as a `copy` prop from `__('<page-name>')` (one flat file per page in
`lang/en` and `lang/nl`). Shared layout copy is the `layoutCopy` prop from
`HandleInertiaRequests`. `HandleLocale` picks the locale from the user's
`preferred_locale`, then the `locale` cookie, then the app default.

**Files:** vendor logos and service media go on the `r2` disk (Cloudflare R2,
S3 driver). Local runs need the `CLOUDFLARE_R2_*` values in `.env`.

**Frontend:** pages are resolved from `resources/js/pages/**/*.tsx` by name
(`Inertia::render('OverviewPage')`). Public and dashboard layouts have separate
desktop and mobile variants under `resources/js/layouts/`. The React Compiler
is on, and SSR is off.

**Deploy:** a FrankenPHP image (`Dockerfile`) builds assets with Bun and runs
Wayfinder generation. `deploy.sh` pulls the image, migrates, and runs
`optimize`.

## Worktrees and branches

Worktrees live in `.claude/worktrees/<name>`. They need `.env` and `vendor/`
copied from the main checkout (never symlink `vendor`), and they share the main
checkout's Sail stack and database through `COMPOSE_PROJECT_NAME`. The full steps
are in `docs/local-development.md`. Feature work branches from `develop`, not
`master`.
